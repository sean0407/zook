# Zook 開發規劃

進度的唯一依據。流程見 [CLAUDE.md](../CLAUDE.md)「每個項目的流程」。

狀態：⬜ 未開始　🟨 進行中　✅ 完成　⏸ 暫緩

## 已決定的事（2026-11-18）

- Bot 建立、修改、刪除排程，每次都要使用者核准，不論權限模式。
- Mac 關機時不跑排程，不做雲端主機。
- 進階選項（思考強度、各家特色）收在「進階」裡，主畫面保持簡單。
- 開發採「逐階段」：使用者核准該階段的驗收條件，之後依序做完，卡住或驗收失敗才停。

## 已完成（v0.6.0 以前）

Bot 與分組、群聊（管理員主持、互相交接）、多帳號、備用模型自動切換、共用 Skill／連接器／插件、匯入 Zook 與設定包、內建 Gmail（個人帳號）、記憶、知識庫、上網搜尋開關、用量、單一 Bot 排程、iPhone App、自動更新。

- D4：通過。只一次執行後停用並顯示「已完成」；每月 31 號遇小月在月底；舊排程照常（`ScheduleTimes`、瀏覽器實測）。
- D6：通過。保留最近 20 次；「紀錄」點一筆會開到該訊息並標示（瀏覽器實測）。
- D3：通過，點通知未驗證。Preview 版以真實 Codex 跑排程，App 把通知交給 macOS 成功；macOS 第一次會先問是否允許通知。點通知開啟對話在瀏覽器以相同程式碼驗證，真實點擊待使用者驗收。
- E1：Codex、Claude、Grok 通過（列出不用核准；建立、修改、刪除在三種主動性都要核准；上限 50）。**Gemini 未通過**：Gemini CLI 目前完全沒有接 Zook 工具，這台 Mac 也沒裝 Gemini，改列 E6。
- D2：通過。真實 Codex、Claude、Grok 一句話建立排程；拒絕時不建立且 Bot 說明；群組裡建出群組排程；「全部允許」的 Grok 仍要核准；手機 API 拿到同樣的核准說明。手機實機待使用者驗收。
- G1：通過。寄信卡片寫出收件人與主旨；排程執行中要核准時發通知，真實 Codex、Claude 等 100 秒後核准仍正常完成；逾時視為拒絕並寫入紀錄（以縮短的等待時間測試）。

順帶修好的既有問題（Grok）：Zook 工具在 App 裡一直沒接上（嚴格沙箱無法啟動 Xcode 內的 Python）；Grok 用短名稱呼叫工具時被擋；新版 Grok 不接受 `--add-dir`，「整台 Mac」「指定資料夾」的 Grok Bot 無法啟動。Grok 的檔案工具現在只在工作資料夾，整台 Mac 改靠指令列；「指定資料夾」的 Grok 碰不到該資料夾。

### D1 群組排程
1. 排程表單的對象下拉同時列出 Bot 和群組。
2. 選群組的排程，時間到會在群組以「由 排程 發起」發話，照平常的群組流程討論，最後由主持 Bot 給結論。
3. 群組正在討論時，等它結束再開始；6 小時後仍在忙就記為錯過。
4. 刪除群組時，它的排程一起刪除；排程卡片顯示群組名稱與頭像。
5. 「立即執行」對群組排程也有效。

### D4 單次與更多頻率
1. 重複方式增加：只一次（選日期）、每小時、每月（選幾號）。
2. 只一次的排程執行後自動停用，卡片顯示「已完成」。
3. 每月選 29–31 號時，遇到沒有這天的月份在該月最後一天執行。
4. 舊版建立的排程照常運作。

### D6 執行紀錄
1. 每個排程保留最近 20 次執行：時間、結果（已執行／失敗／錯過）、原因。
2. 卡片上「紀錄」打開列表，點其中一筆跳到那次的對話位置。
3. 刪除排程時紀錄一起刪除。

### D3 完成通知（Mac）
1. 排程執行完（回覆完成、失敗或錯過）跳出 Mac 通知，標題是對象名稱，內文是結果的第一句。
2. 排程執行中出現需要核准的動作時，也跳通知。
3. 點通知會開啟 Zook 並切到該對話。
4. 設定裡有「排程通知」開關，預設開啟。

### E1 Zook 動作工具（排程）
1. Codex、Claude、Grok、Gemini 的 Bot 都拿得到一組 Zook 工具：列出、建立、修改、刪除排程。設定一次，全體共用。
2. 列出不用核准；建立、修改、刪除都要核准。
3. 工具只能管理排程，不能改權限、存取範圍、模型、帳號或其他設定。
4. 上限：全部最多 50 個排程；超過時工具回覆原因。
5. 每個 Bot 的工作說明裡告訴它「可以幫使用者建立排程」。

### D2 Bot 在對話裡建排程
1. 在 Bot 對話說「每天早上 10 點…」，Bot 提出排程，Mac 和手機都出現核准卡片，寫出對象、內容、時間與頻率。
2. 按核准才建立，Bot 回覆建好了什麼；按拒絕不建立，Bot 回覆已取消。
3. 在群組裡說，建出來的是群組排程。
4. 權限模式是自動核准的 Bot 也一樣要核准。
5. 建好的排程出現在排程頁，和手動建立的完全一樣。

### G1 對外動作一律核准
1. 寄信、建立／修改／刪除排程，不論權限模式都要核准；核准卡片寫出要做什麼。
2. 排程無人看管時遇到核准請求，等待最多 24 小時，期間發通知；逾時視為拒絕，記入執行紀錄。

### 第 1 階段需要使用者驗收
- 在 Zook 視窗裡用真實的 Claude 或 Codex 說一句話建立排程。
- 在手機上按核准。
- 收到 Mac 通知、點通知開啟對話。
- 隔天確認排程在 10:00 自動執行。

## 第 2 階段：對話體驗

目標：和 Bot 對話的手感接近 ChatGPT／Claude：可以開新對話、找回舊對話、丟檔案和截圖、不滿意就重來、需要時讓它想深一點或先給計畫。

| B3 | 重新回答、修改問題重送、換模型重答 | ✅ |
| B2 | 附件：拖放檔案、貼上截圖 | ✅ 限制見報告 |
| A3 | 思考強度（快速／標準／深入） | ✅ |
| B5 | 先規劃開關 | ✅ |

### 第 2 階段驗收報告（v0.8.0）

自動測試 179 項、臨時伺服器加內建瀏覽器實測、真實 CLI 實測三層都做過，並經獨立 AI 審查（10 項問題已全部修正）。

- B1：通過。新對話、清單、改名、刪除、跨 Bot 搜尋與跳轉；切換後回覆仍回到原對話；排程寫進「排程」對話；舊資料成為第一個對話。手機顯示目前開著的對話。
- B3：通過。重新回答、編輯重送、換模型重答（Bot 設定不變）；上一次做過動作時先提醒；重答失敗或被停止時，原本的問答會放回去；先規劃的訊息重答後仍是先規劃。
- B2：通過，有一項限制。貼上、拖放、選檔都可用；真實 Codex、Claude、Grok 都看得到圖片，後續追問也看得到；群組成員輪到時會收到檔案。**限制**：謹慎模式的 Codex 只能看圖片和文字檔（128 KB 內），PDF 等其他檔案要改用自動以上的主動性。
- A3：通過。快速、深入在真實 Codex、Claude、Grok 都正常；不支援的 CLI 顯示說明。
- B5：通過。全部允許模式下，真實 Codex、Claude、Grok 在計畫階段都沒有建立檔案，按「照計畫執行」後才建立。計畫中 Zook 的寫入工具不提供、變更一律拒絕、讀外部服務要核准；Zook 無法限制成唯讀的 CLI（Gemini、自訂 CLI）不提供先規劃。

順帶修好：共用 Skill 要求派子代理時，Bot 不再停下來，改由自己完成。

### B1 每個 Bot 多個對話
1. Bot 對話畫面有「新對話」按鈕；新對話從空白開始，Bot 不會看到其他對話的內容（記憶與知識庫照舊共用）。
2. 有對話清單：依最近使用排序，標題自動取第一句，可以改名、刪除（刪除前確認）。
3. 搜尋框可以搜所有 Bot 的對話內容，點結果開到該對話的那則訊息。
4. 舊版的對話成為每個 Bot 的第一個對話，內容不變。
5. 排程送出的訊息進到該 Bot 的「排程」對話，不打斷你正在進行的對話；排程紀錄與通知仍能開到正確位置。
6. 手機看到每個 Bot 最近的對話，可以在其中繼續聊天；切換對話清單留到第 5 階段 F1。

### B3 重新回答、修改問題重送、換模型重答
1. Bot 最後一則回覆下方有「重新回答」：用同一個問題再回答一次，舊回覆被取代。
2. 自己的最後一則訊息可以「編輯」，改完重送，之後的回覆被取代。
3. 「換模型重答」下拉列出已安裝可用的模型；重答只用這一次，不改 Bot 設定，回覆下方註明用了哪個模型。
4. Bot 正在回覆、或回覆時曾經改過檔案或對外動作時，重答前先提醒「上一次已經做過的動作不會復原」。
5. 群組不提供這三個功能（第 4 階段再說）。

### B2 附件
1. 可以把檔案拖進對話框、按「＋」選檔案，或直接貼上截圖；送出前看得到縮圖或檔名，可以移除。
2. 每則訊息最多 10 個檔案，單檔 20 MB；超過時說明原因，不送出。
3. 檔案存進該 Bot 的工作資料夾，Codex、Claude、Grok 都讀得到；圖片 Codex 直接看圖，Claude、Grok 用自己的讀檔工具看。
4. 對話裡顯示附件（圖片顯示縮圖，點開放大；其他檔案顯示檔名）。
5. 群組也可以附檔，所有成員都讀得到。
6. 手機暫不支援附檔（第 5 階段 F1）。

### A3 思考強度
1. 對話框旁有下拉：快速／標準／深入，預設「標準」，只影響之後的訊息；在「進階」裡可以設定每個 Bot 的預設值。
2. Codex、Claude、Grok 各自對應到自己的強度設定；CLI 不支援時選項顯示「這個模型不支援」並停用。
3. 回覆下方可以看到這次用了哪個強度（只有不是「標準」時才顯示）。

### B5 先規劃開關
1. 對話框旁有「先規劃」開關。開啟時 Bot 只提出計畫（要做什麼、會動到什麼、需要哪些核准），不動檔案、不執行指令、不做對外動作。
2. 計畫下方有「照計畫執行」按鈕，按下後 Bot 依計畫執行，核准規則照常。
3. 開關只對這一則訊息有效，送出後自動關閉。

### 第 2 階段需要使用者驗收
- 在 Zook 視窗開新對話、從清單切回舊對話、用搜尋找到一則舊訊息。
- 貼一張截圖問 Claude 或 Codex 圖裡是什麼。
- 對一則回覆按「換模型重答」。
- 用「深入」問一個難題，再用「先規劃」讓 Bot 提計畫、按照計畫執行。

### 第 3 階段驗收報告（v0.9.0）

自動測試 222 項、臨時伺服器加內建瀏覽器實測、真實 CLI 實測三層都做過，並經兩輪獨立 AI 審查（問題已全部修正）。

- G6：通過。後端與介面拆成多個檔案，每個檔案不超過 1000 行，行為不變。
- A1：通過。四家 CLI 的能力清單顯示在模型卡片上；CLI 改版少了某個選項時，只關閉受影響的功能並提示。
- A2：通過。Codex、Claude、Grok、Antigravity 都能接續自己的對話；接不上時改用 Zook 保存的內容。換帳號、模型、資料夾、存取範圍或主動性時會開新對話；只有 CLI 明確回報對話不存在才重跑，逾時或其他失敗不重跑，避免同一件事做兩次。
- A4：通過，範圍比原訂小。多代理協作開放 Codex、Claude、Grok；圖片生成開放 Codex、Grok（Grok 需要全部允許和整台 Mac）。**沒有開放**：瀏覽器操作（沒有一家 CLI 實測完成）；Antigravity 的兩項功能（子代理不穩定、圖片生成常遇到容量錯誤）。

順帶修好：內建指令裡的金鑰、密碼在寫入活動紀錄前會遮蔽，舊紀錄在啟動時一併處理。

**未查明**：發佈前的檢查中，Codex 有 3 次送出請求後模型一直沒回應（都在同一天 14:31–14:58）。之後用同一版連續測 50 次都正常，沒有重現，原因未確定。

### G6 拆開大檔案
1. `backend/server.py` 和 `frontend/app.js` 依功能拆成多個檔案，單檔不超過 1000 行；仍然不需要安裝任何套件或建置步驟。
2. 只搬程式、不改行為：全部自動測試、App 檢查和真實 CLI 檢查都照常通過。
3. 舊資料不需轉換，更新後所有 Bot、對話、排程和設定都還在。

### A1 能力對照表與自動檢查
1. Zook 內有一份各家能力對照表：對話、Zook 工具、看圖、先規劃、思考強度、原生對話、額度讀取。
2. 每張模型卡片列出這個 CLI 目前能用的能力。
3. CLI 更新後，Zook 自動檢查它需要的參數還在不在，不花模型額度。
4. 檢查不過時，卡片寫出哪個功能受影響；能關掉的功能自動關閉，其他功能照常。
5. 「一鍵全更新」完成後也跑這項檢查。

### A2 沿用 CLI 原生對話
1. Codex、Claude、Grok、Antigravity 的 Bot 接續同一段 CLI 對話，不再只帶最近 12 則訊息；問 30 則訊息前的內容也答得出來。
2. 每個 Zook 對話對應自己的 CLI 對話；開新對話就從空白開始，切換對話不會混在一起。
3. 換模型、換帳號、重新回答或編輯問題時，改用 Zook 保存的對話內容開新的 CLI 對話，不會接錯內容。
4. CLI 對話接不上（過期、被刪除）時自動改用 Zook 保存的內容，並在回覆下方註明。
5. 主動性、存取範圍和先規劃每次都重新套用，不會沿用上一輪的權限。
6. 排程沿用自己的「排程」對話；群組維持現行做法。

### A4 各家特色開關
1. Bot 的「進階設定」新增三個開關，預設關閉，只顯示這個 CLI 真的支援的項目：多代理協作、瀏覽器操作、圖片生成。
2. 每個開關都要用真實 CLI 實測通過才開放；做不到的項目不顯示。
3. 謹慎和先規劃時一律不啟用；寄信、改排程等動作照常要核准。
4. 回覆的活動紀錄看得出用了哪個特色功能。

### A5 依任務與額度選模型
1. Bot 的模型下拉新增「自動選擇」；原本指定模型的 Bot 完全不受影響。
2. 使用者勾選哪些模型可以被自動選用。Antigravity 因帳號風險預設不勾選，API 計費帳號也預設不勾選。
3. Zook 依任務類型（簡短問答、寫程式、看圖、長篇分析）和訊息內容選模型，不多花一次模型請求。
4. 剩餘額度低於 10% 的模型不選；全部都不夠時告訴使用者，不自動改用付費方式。
5. 回覆下方註明這次用了哪個模型和原因；可以用「換模型重答」改掉。

### 第 3 階段需要使用者驗收
- 和 Bot 聊一段長對話，問很前面提過的內容。
- 在開著的模型卡片看能力清單，按一次「一鍵全更新」。
- 開啟一個特色開關，實際用一次。
- 建一個「自動選擇」的 Bot，問不同類型的問題，看選了哪個模型。

### 第 5 階段驗收報告（v0.11.0）

自動測試 288 項、臨時伺服器加內建瀏覽器實測，並經兩輪獨立 AI 審查（問題已全部修正）。這一階段有幾項只能驗到一半，逐項寫明。

- E2：程式通過，**完整登入待使用者驗收**。對 Notion、Linear、Sentry 的真實連接器，Zook 找得到登入服務並開得出登入頁；登入、換發、過期更新、登出的完整流程用模擬服務測過。真實帳號的登入要使用者在瀏覽器完成。LogiQ 和 Google Chat 的 403：它們是綁在 Claude／ChatGPT 帳號的連接器，授權由該服務保管，複製到 Zook 的只有網址，所以被拒絕。現在可以在 Zook 新增網址後按「登入」；對方服務不支援公開登記時仍無法使用。另外，沒登入的連接器不再讓整則回覆失敗。
- E3：程式通過，**真實 Google 帳號待使用者驗收**。登入、讀信、讀行事曆、搜尋雲端硬碟、寄信都用模擬的 Google 服務測過；寄信、改行程、上傳和修改檔案在全部允許模式也一律先問。需要使用者自己建立 Google Cloud 用戶端。限制：個人帳號在「測試」狀態下每 7 天要重新登入；雲端硬碟只能修改 Zook 自己上傳的檔案；讀檔上限 128 KB。
- B4：通過。真實 Codex 產出檔案後出現在「產出」分頁，可預覽、下載、在 Finder 顯示，回覆裡的檔名可以點開。只列出工作資料夾裡的檔案，以及回覆期間確實被改過的檔案；連結檔一律不列。
- F1：**未在手機或模擬器實測**。這台 Mac 沒有可用的 iPhone 模擬器。App 編譯通過，Mac 端的手機介面有自動測試。真正的推播見 F2。
- B6：通過。專案的說明、資料夾和知識只帶給專案裡的 Bot；一個 Bot 只屬於一個專案；刪除專案不會刪 Bot、群組或檔案。專案資料夾不會放寬 Bot 的存取範圍。

### E2 連接器在 Zook 裡登入授權
1. 需要登入的遠端連接器，卡片上有「登入」按鈕，在瀏覽器完成授權後回到 Zook。
2. 授權資料只存在 macOS 鑰匙圈，不寫進資料檔、指令列或紀錄，也不傳到手機。
3. 授權過期時自動更新；更新失敗時卡片顯示「需要重新登入」。
4. 可以登出，登出後授權資料從鑰匙圈刪除。
5. 用至少一個真實的遠端連接器實測。LogiQ 和 Google Chat 的 403 一併查原因，查不出來就明確記錄。

### E3 Gmail、行事曆、雲端硬碟
1. 設定頁可以用 Google 帳號登入，取代應用程式密碼；原本的方式保留。需要使用者自己建立 Google Cloud 授權憑證，公司管理員可能擋下。
2. Bot 可以讀信、搜尋信、讀行事曆、搜尋和讀取雲端硬碟檔案。
3. 寄信、建立或修改行程、上傳或修改檔案，一律要使用者核准，不論主動性。
4. 權限只申請用得到的範圍，讀取和寫入分開，可以只開讀取。

### B4 產出物面板
1. Bot 詳情新增「產出」分頁，列出這個 Bot 建立或修改過的檔案，最新的在前。
2. 可以預覽文字、Markdown、圖片和 PDF，也可以在 Finder 顯示或下載。
3. 回覆裡提到產出檔案時，可以點開預覽。
4. 只列出檔案，不放寬 Bot 的存取範圍。

### F1 手機
1. 手機可以查看、暫停、啟用和刪除排程；新增和修改只在 Mac 上做。
2. 手機可以拍照或從相簿選照片當附件，每則最多 4 張。
3. 手機可以切換同一個 Bot 的不同對話。
4. 回覆完成、需要核准、排程執行完時，手機跳出本機通知（App 開啟或在背景短時間內；真正的推播見 F2）。
5. 金鑰和授權資料不會傳到手機。

### B6 專案
1. 可以建立專案，把 Bot、群組和知識放進去；左側可以依專案篩選。
2. 專案可以設定一個資料夾和一段說明，專案裡的 Bot 回覆時會帶入。
3. 沒放進專案的 Bot 和群組行為不變。
4. 刪除專案不會刪除裡面的 Bot、群組或檔案。

### 第 5 階段需要使用者驗收
- 在一個需要登入的連接器按「登入」，請 Bot 用它查一筆資料。
- 請 Bot 整理今天的信和行程，再請它擬一封信，確認寄出前會先問。
- 請 Bot 產出一個檔案，到「產出」分頁預覽。
- 用手機拍一張照片問 Bot，再暫停一個排程。
- 建一個專案，把一個 Bot 放進去問問題。
