# Zook 開發規劃

進度的唯一依據。流程見 [CLAUDE.md](../CLAUDE.md)「每個項目的流程」。

狀態：⬜ 未開始　🟨 進行中　✅ 完成　⏸ 暫緩

## 方向收斂計劃（2026-11-22 定案，尚未動手）

2026-11-22 使用者與方向盤點對話定案。**狀態：已定案，尚未動手；只寫計劃。** 產品改動由「ZOOK開發」一版一件事依序做，發佈照現行流程。每一項動手前，先問使用者第四節列的事。

### 一、不變的核心（之後不列為收斂對象）

1. **一個 Bot 是一家模型的個體，底層是各家 CLI。**
2. **群組由主持人帶**：分工、設邊界、決策關卡、跨家驗收。這是讓答案可靠的機制。
3. **多模型必要的選項**：模型與帳號、思考強度、備用模型、自動選擇。自動選擇的意思改成「建 Bot 時就配好合適的模型」，不再每則訊息換一家，見 D。
4. **共用工具層**：連接器、Gmail、Google、瀏覽器、共用 Skill 與 MCP，授權一次，全部 Bot 和各家 CLI 共用。
5. **Grok Bot 也有的能力**：多代理協作、內建瀏覽器、圖片生成。

### 二、做法的改變

- **不再一直往上加功能。** 問題由「模擬員工巡檢」找出來，優先打磨通用機制（流程、Skill、範本、提示、介面）。
- **新功能的門檻**：同一個缺口在兩個以上行業都出現，才考慮做成新功能。
- **路線圖的來源**：使用者自己使用改為補充來源，主要來源是巡檢。

### 三、要做的事（建議順序）

#### A. 模擬員工巡檢（改每日巡檢，不動產品程式）

1. **題庫**：各行業（行銷、業務、行政會計、人資、客服、零售通路、專案管理）乘以常見交辦（寫信、報表、簡報、填表、會議紀錄、比價、企劃）。每題包含：
   - 模擬員工的身分：不懂程式、口語交辦、資訊常常不全；
   - 交辦內容；
   - 附件：用合成資料，不用使用者公司的真實資料；
   - 驗收標準。
2. **執行**：像真員工一樣在 Zook 介面交辦，單一 Bot 和群組都要測，每天輪換幾題。測試時可以用本機腳本指令批次送題。
3. **額度**：只用訂閱額度，每次約 20 次模型回覆，額度低於 20% 就跳過要用模型的項目。
4. **成果檔案驗收**（Excel、PDF、Word、簡報、設計圖）：
   - 真的產出檔案，不是只貼文字或說「已完成」；
   - 檔案類型對、打得開；
   - 內容正確，例如數字、公式、頁數、尺寸；
   - 版面符合交辦：轉成圖片實際看過，不只讀文字；
   - 在 Zook 裡預覽正確，Mac 和手機都能下載。
5. **評分**：
   - 能不能直接用；
   - 有沒有假完成；
   - 返工幾次，其中「格式不對」單獨計次；
   - 花多少時間和額度；
   - 卡在介面哪裡；
   - 跨家驗收擋下幾次錯誤。
6. **報告**：
   - 每天一份白話網頁，推到手機，列出分數趨勢；
   - 小問題交給 ZOOK開發開 PR；
   - 會改變功能或做法的，列出來讓使用者挑。

#### B. CLI 收斂成 6 家（使用者 2026-11-22：保留 Cursor）

- **保留**：Codex、Claude、Grok、Antigravity、Gemini、Cursor。
- **移出**（程式和測試都刪掉，不是隱藏）：OpenCode、GitHub Copilot、Kimi。
- 之後不再接新的 CLI。
- **一併處理**：
  - 已經在用那 3 家的 Bot 怎麼轉，並告知使用者；
  - 自動選擇的名單；
  - 能力檢查；
  - 測試與 acceptance.py 的範圍。
- Gemini 的工具卡住問題（ROADMAP E6）要先確認。

#### C. 編輯 Bot 選項精簡（改到權限，用 astra 審查）

- **存取範圍比照 Grok Bot**：預設就有很大的權限，不用另外選；遇到安全邊界一律先問；對外動作一律核准照舊。
- **移除「主動性」。**
- **本機腳本**：拿掉編輯 Bot 裡的開關；`zook-cli` 指令保留，只給內部測試用，例如巡檢批次送題。
- 已設了主動性、存取範圍的 Bot 和設定要轉換。
- 之前交辦的「指定資料夾範圍內 Codex 不能 git commit」：如果 C 拿掉「指定資料夾」，就不用修。

#### D. 建 Bot 時配模型，設定一律跟著預設（2026-11-22 補充）

1. **自動選擇改在建 Bot 時決定**：
   - 依 Bot 的人格和工作指示，判斷它的工作適合哪一家、哪個模型，在建立時配好。
   - 之後每次回答都用同一個模型，不再每則訊息換一家。這樣也符合「一個 Bot 是一家模型的個體」。
   - 配好的模型要顯示在 Bot 設定裡，並附一句理由（例如「寫程式多，配 Codex」），使用者可以手動改。
   - 額度用完時，照舊由備用模型接手；這是暫時的，不改 Bot 本身配的模型。
2. **單一 Bot 的設定一開始全部用預設**：
   - 選單直接寫目前的值，加上「（預設）」，例如「全部允許（預設）」。
   - 不再寫成「使用預設（全部允許）」這種長句。
3. **預設值只在「設定」頁改一次，整個工具連動**：
   - 停在「（預設）」的 Bot 會跟著設定頁一起變。
   - 個別改過的 Bot 維持自己的值，並且可以一鍵改回預設。

**順序理由**：A 不動產品程式，可以最先開始，後面的取捨也要靠它的數據。B 是純減法，做完之後每版的測試和驗收都會變快。C 改到權限，風險最高，放在 B 之後。D 和 C 都改到編輯 Bot 的畫面，D 接在 C 後面做，或與 C 合併成同一版，避免同一批檔案改兩次。

## 已決定的事（2026-11-18）

- Bot 建立、修改、刪除排程，每次都要使用者核准，不論權限模式。
- Mac 關機時不跑排程，不做雲端主機。
- 進階選項（思考強度、各家特色）收在「進階」裡，主畫面保持簡單。
- 開發採「逐階段」：使用者核准該階段的驗收條件，之後依序做完，卡住或驗收失敗才停。

### D1 群組排程
1. 排程表單的對象下拉同時列出 Bot 和群組。
2. 選群組的排程，時間到會在群組以「由 排程 發起」發話，照平常的群組流程討論，最後由主持 Bot 給結論。
3. 群組正在討論時，等它結束再開始；6 小時後仍在忙就記為錯過。
4. 刪除群組時，它的排程一起刪除；排程卡片顯示群組名稱與頭像。
5. 「立即執行」對群組排程也有效。

### D4 單次與更多頻率
1. 重複方式增加：只一次（選日期）、每小時、每月（選幾號）。
2. 只一次的排程執行後自動停用，卡片顯示「已完成」。
3. 每月選 29–31 號時，遇到沒有這天的月份在該月最後一天執行。
4. 舊版建立的排程照常運作。

### D6 執行紀錄
1. 每個排程保留最近 20 次執行：時間、結果（已執行／失敗／錯過）、原因。
2. 卡片上「紀錄」打開列表，點其中一筆跳到那次的對話位置。
3. 刪除排程時紀錄一起刪除。

### D3 完成通知（Mac）
1. 排程執行完（回覆完成、失敗或錯過）跳出 Mac 通知，標題是對象名稱，內文是結果的第一句。
2. 排程執行中出現需要核准的動作時，也跳通知。
3. 點通知會開啟 Zook 並切到該對話。
4. 設定裡有「排程通知」開關，預設開啟。

### E1 Zook 動作工具（排程）
1. Codex、Claude、Grok、Gemini 的 Bot 都拿得到一組 Zook 工具：列出、建立、修改、刪除排程。設定一次，全體共用。
2. 列出不用核准；建立、修改、刪除都要核准。
3. 工具只能管理排程，不能改權限、存取範圍、模型、帳號或其他設定。
4. 上限：全部最多 50 個排程；超過時工具回覆原因。
5. 每個 Bot 的工作說明裡告訴它「可以幫使用者建立排程」。

### D2 Bot 在對話裡建排程
1. 在 Bot 對話說「每天早上 10 點…」，Bot 提出排程，Mac 和手機都出現核准卡片，寫出對象、內容、時間與頻率。
2. 按核准才建立，Bot 回覆建好了什麼；按拒絕不建立，Bot 回覆已取消。
3. 在群組裡說，建出來的是群組排程。
4. 權限模式是自動核准的 Bot 也一樣要核准。
5. 建好的排程出現在排程頁，和手動建立的完全一樣。

### G1 對外動作一律核准
1. 寄信、建立／修改／刪除排程，不論權限模式都要核准；核准卡片寫出要做什麼。
2. 排程無人看管時遇到核准請求，等待最多 24 小時，期間發通知；逾時視為拒絕，記入執行紀錄。

### 第 1 階段需要使用者驗收
- 在 Zook 視窗裡用真實的 Claude 或 Codex 說一句話建立排程。
- 在手機上按核准。
- 收到 Mac 通知、點通知開啟對話。
- 隔天確認排程在 10:00 自動執行。

順帶修好：共用 Skill 要求派子代理時，Bot 不再停下來，改由自己完成。

### B1 每個 Bot 多個對話
1. Bot 對話畫面有「新對話」按鈕；新對話從空白開始，Bot 不會看到其他對話的內容（記憶與知識庫照舊共用）。
2. 有對話清單：依最近使用排序，標題自動取第一句，可以改名、刪除（刪除前確認）。
3. 搜尋框可以搜所有 Bot 的對話內容，點結果開到該對話的那則訊息。
4. 舊版的對話成為每個 Bot 的第一個對話，內容不變。
5. 排程送出的訊息進到該 Bot 的「排程」對話，不打斷你正在進行的對話；排程紀錄與通知仍能開到正確位置。
6. 手機看到每個 Bot 最近的對話，可以在其中繼續聊天；切換對話清單留到第 5 階段 F1。

### B3 重新回答、修改問題重送、換模型重答
1. Bot 最後一則回覆下方有「重新回答」：用同一個問題再回答一次，舊回覆被取代。
2. 自己的最後一則訊息可以「編輯」，改完重送，之後的回覆被取代。
3. 「換模型重答」下拉列出已安裝可用的模型；重答只用這一次，不改 Bot 設定，回覆下方註明用了哪個模型。

5. 群組不提供這三個功能（第 4 階段再說）。

### B2 附件
1. 可以把檔案拖進對話框、按「＋」選檔案，或直接貼上截圖；送出前看得到縮圖或檔名，可以移除。
2. 每則訊息最多 10 個檔案，單檔 20 MB；超過時說明原因，不送出。
3. 檔案存進該 Bot 的工作資料夾，Codex、Claude、Grok 都讀得到；圖片 Codex 直接看圖，Claude、Grok 用自己的讀檔工具看。
4. 對話裡顯示附件（圖片顯示縮圖，點開放大；其他檔案顯示檔名）。
5. 群組也可以附檔，所有成員都讀得到。
6. 手機暫不支援附檔（第 5 階段 F1）。

### A3 思考強度

3. 回覆下方可以看到這次用了哪個強度（只有不是「標準」時才顯示）。

### B5 先規劃開關

2. 計畫下方有「照計畫執行」按鈕，按下後 Bot 依計畫執行，核准規則照常。
3. 開關只對這一則訊息有效，送出後自動關閉。
