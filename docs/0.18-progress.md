## 做了什麼

- **剩餘額度卡片**（`frontend/js/32b-cards.js`）：每個帳號一張、所有卡片同樣大小（格線每列等高），同一家的帳號相鄰。卡片只放額度與自動選用；登入狀態、帳號、方案、版本與更新、能力、登出與移除收進「詳細」。原本的「帳號與版本」區塊與每家的 Zook 用量拿掉（用量總覽已涵蓋）。沒安裝的 CLI 只出現在「＋ 新增模型」的「已加入、尚未安裝」。
- **每個帳號都能被自動選擇**（`routing.py`）：額外帳號的狀態與額度用 `CLI@帳號` 為鍵；開關存在 `settings.autoAccounts`，使用者沒設定時，已登入的訂閱帳號預設開啟（與預設帳號相同），API 計費的帳號一律關閉而且不能打開。選擇結果的第三個元素是帳號，回覆（`app.py`）、群組、任務引擎（派工、驗收、同時上限的計算）都照這個帳號執行；備用切換的提示寫出帳號名稱。
- **用量總覽**（`32-usage.js`、`usageview.py`）：Token 用 K／M／B；只留「訂閱帳號不會被收這筆錢。」；未計價改成模型名稱旁的小標；每日圖表依欄寬與左欄高度重畫，下拉選單切換費用／Token（後端多了每家每日 Token）。
- **Grok 額度**（`grokquota.py`）：先試 `grok usage --json`（1.0.89 還不能用）；不行就在看不見的終端機開 Grok，讀畫面底部的「Weekly limit left」，讀完關掉整個程序群組。Grok 要讀鍵盤得有自己的終端機，所以用一個小程式把終端機交給它再換成 Grok。唯一會輸入的是 Grok 問「是否信任」Zook 自己的空資料夾時的「y」，而且輸入後畫面一有變化就不再輸入。讀不到時卡片顯示「讀不到額度」。失敗的讀取十分鐘內不重試，頁面不會一直等。
- **新圖示**：`assets/icon-source.png`、iPhone 的 `icon-1024.png` 換成新圖；左上角的「Zook✳」換成 `frontend/brand.png`（28px、圓角、`aria-label="Zook"`）。
- **Codex 審查**：`scripts/codex_review.py` 只轉給共用的 codex-review Skill；CLAUDE.md 第 6 步改成指向 Skill，只留 Zook 自己的規定。

### astra 安全審查（`92c204b..06c558a` 的安全相關檔案）
Zook 帳號「Waifdance」、`gpt-6.2-astra`、high、約 131,642 token（Codex 預設帳號剩 17%，依 20% 下限跳過）。6 個高、3 個中，處理如下（提交 `c05bd30`）：
- 高 建立團隊在只開額外帳號時繞過自動選擇 → 修：只要知道登入狀態就交給自動選擇；選不到時用「設定」裡的預設模型與它自己的登入（和一般使用預設模型的 Bot 相同），不再用帶著帳號的 Bot。
- 高 備用與重試沒有再檢查帳號 → 修：每次嘗試前都檢查開關、帳號是否存在、是否屬於這個 CLI、是否計費、是否確認是訂閱。
- 高 開關可以代替「確認是訂閱」→ 修：執行前也要求確認是訂閱、未計費。登入檢查失敗時保留上次結果（`merge_auto_status`）是 0.9 起的既有行為，這版沒改。
- 高 Grok 的 `api_key` 設定與 OpenCode 付費模型可能計費 → 沒改：判斷方式是既有的（Grok 從 0.9、OpenCode 從 0.16，OpenCode 的自動選擇預設關閉），列入之後的項目。
- 高 備份還原帶回開關與帳號定義 → 部分修：型別錯誤的開關視為沒設定。還原就是回到當時的設定，所以帶回當時的開關是預期的；多台同步不會帶這個設定。
- 高 群組步驟可以冒充「使用者指定模型」→ 修：只有使用者親自的「換模型重答」能指定；群組步驟帶不進這個標記、帳號選擇或執行紀錄。
- 高 Grok 可能對已消失或偽造的信任問題輸入「y」→ 修：畫面上從最後一個信任問題起，只能有這個資料夾的路徑和信任問題本身的文字，才輸入一次「y」，之後不再輸入。審查建議完全不輸入、改由使用者第一次手動信任；這版保留自動回答，因為範圍已限定在 Zook 自己的空資料夾。
- 高 資料夾不保證是空的 → 修：不是空的、是連結、不是本人的或別人能進的，就不開 Grok。
- 中 探測帶著後端的全部環境變數 → 修：只帶 Grok 需要的（家目錄、路徑、語言、代理、暫存）。
- 中 程序群組可能誤殺、關閉後端時留下程序 → 修：在回收前結束整個群組；後端結束時偽終端關閉，Grok 會收到結束訊號，JSON 探測最多 20 秒。
- 中 JSON 輸出沒有上限、等待沒有總上限 → 修：輸出最多 64KB；同一帳號讀取中時第二個請求直接拿上次結果，不排隊。

## 0.18.4：群組討論中可以插話
